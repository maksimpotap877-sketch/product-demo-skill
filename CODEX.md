# Инструкции для Codex

Прочитайте [README.md](README.md), [Skill](skills/product-demo/SKILL.md) и [рабочий процесс](docs/WORKFLOW_RU.md). Подключение клиента и Remotion: [clients.md](docs/clients.md). Установка: [INSTALL_RU.md](docs/INSTALL_RU.md).

Перед видео другого продукта прочитайте его инструкции, запуск, маршруты, компоненты и логику выбранной функции. Заполните demo.understanding.json по действительно прочитанному коду. Проверьте признак успеха в браузере без записи. Без валидного разбора нельзя выполнять capture или render. Не обходите ограничение попыток новой папкой.

При изменении toolkit изучите src/schema.ts, src/cli.ts и модуль нужной стадии. Проверяйте установку из архива, а не только запуск из исходников. Сохраняйте pinning зависимостей и независимый runtime. Проверки: npm run typecheck, npm test, npm run build. Сетевые тесты озвучки требуют разрешения на внешний TTS.

Native capture fps и render fps указывайте отдельно. Не объявляйте прослушивание, просмотр динамики, Claude/GLM E2E или сторонний вход проверенными без выполнения. Не публикуйте профили, auth, ключи, локальные конфигурации и приватные исходники продукта.

Этот файл — явная стартовая инструкция репозитория. Для автоматических правил Codex добавьте ссылку на него в существующий AGENTS.md своего проекта без перезаписи чужих правил. Переносимый Skill устанавливается штатной командой; локальные runtime-пути с другого компьютера не копируются.

Версия 0.4: до рендера составьте монтажный лист и отберите явные источники/диапазоны; проверьте короткий сложный фрагмент. Камера неподвижна по умолчанию, кадр сохраняет пропорции, переходы не должны удваивать интерфейс. Технический inspect не одобряет монтаж. Сохраните отдельную проверку конкретного MP4 через review; без полного обычного просмотра/прослушивания соответствующие критерии остаются not-tested. См. [docs/EDITING_RU.md](docs/EDITING_RU.md).
