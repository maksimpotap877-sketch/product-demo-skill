# Захват, авторизация и измерения

Проверено на Windows 11, Node 24.19.0, Playwright 1.63.0, Microsoft Edge 153.0.4234.48 и FFmpeg 8.1.1. Проверка: 22 сентября 2026. Системный Edge выбран через публичный `channel: 'msedge'`: загрузка Chromium 1243 с официального CDN завершилась таймаутами. Playwright FFmpeg 1011 уже установлен. Наличие браузера проверяется до выбора канала.

## Два разных показателя

Публичный Playwright `recordVideo` сохраняет реальное видео действий. Документированного параметра 144 fps нет. В реальном example измерены 1600 × 900 и 25 кадров/с в видеопотоке, PNG состояний — 2560 × 1440 при CSS viewport 1600 × 900 и DPR 1.6. Повышенный DPR увеличил разрешение скриншотов; исходное видео осталось 1600 × 900. Частота независимых обновлений реального приложения не измерена и хранится как `unknown`.

Hybrid144 означает скриншоты и низкочастотное видео плюс отдельные покадровые анимации Remotion. Он не является native144. `--strict-native-fps` проверяется **до чтения кеша** и останавливает неподтверждённый Playwright-захват.

`benchmark` использует собственную страницу с движением, текстом и 16-битным визуальным счётчиком. Счётчик меняется один раз на `requestAnimationFrame`. После полного декодирования FFmpeg измеряются временные метки и значения чёрных/белых ячеек. Независимым обновлением считается изменение декодированного числа, а не шум сжатия. Допуски: минимум две секунды, не менее 97% от целевого количества обновлений, максимальный интервал — три целевых кадра. Сохраняются все числовые маркеры, timestamps и журнал браузерного счётчика.

В выполненном тесте Playwright: 1280 × 720, поток 25 fps, около 21.6 измеренных уникальных обновлений/с на выбранном интервале. Это `degraded`. Показатель включает наблюдаемые повторения; он не выводится из заголовка файла.

Проверены документированные Windows-пути FFmpeg. Запись GDI направлена строго в HWND отдельного браузера; она действительно выполнена, но дала чёрные кадры, визуально проверенные в `output/benchmark/gdigrab-first.png`. Маркер не декодируется, статус `blocked`. Desktop Duplication не запускается при неподтверждённом fullscreen либо неподтверждённом физическом client crop и foreground HWND. В этой среде fullscreen не был подтверждён; системная проверка foreground для безопасного crop тоже не прошла. Рабочий стол целиком не записывался, частота экрана не менялась. Native144 **не достигнуты**. Наличие 165 Hz монитора не меняет этот вывод.

## Сценарии и часы

Поддерживаются semantic locators: `role/name`, `label`, `text`, `testid`, `css`. Неоднозначный locator даёт ошибку. `resolveLocator(page, locator)` также принимает обычный Playwright Locator в библиотечном API, но CLI-конфиг исполняет только сериализуемый список действий. Произвольный сценарий-функция пока не поддержан.

Действия: click, fill/type, hover, scroll, waitFor, pause, marker, screenshot. Сначала выполняется отдельный пробный проход загрузки страницы и проверки readiness без записи, screenshots и бизнес-действий. В capture ожидание интерфейса опирается на видимый locator, загрузку шрифтов/изображений с ограниченными таймаутами. `networkidle` не используется. Единственная основная страница поддерживает полные навигации; popup закрывается с понятной ошибкой. Адресуемые iframe-сценарии не реализованы.

`pointerdown`, `input`, `wheel` фиксируются обработчиком страницы. Сохраняются фактическое время, актуальная геометрия цели и координаты; значения полей не сохраняются. Парольные, почтовые, телефонные и платёжные поля блокируются для записываемого заполнения. Это дополнительная защита, а не полная классификация PII. Тестовые приложения используют только вымышленные локальные данные.

До и после полезного фрагмента добавляется пурпурный технический маркер. Его появление декодируется из видео. `sourceStartMs/sourceEndMs` исключают маркеры из монтажа. Время страницы и видео связывает аффинное преобразование по двум опорным точкам; часы Node имеют отдельно измеренное смещение. При исходном дрейфе больше двух исходных кадров + round-trip clock mapping получает `degraded`; больше 250 мс или отклонение масштаба более 5% — capture останавливается. `uncertaintyMs` включает измеренный дрейф, один исходный кадр и round-trip. Нелинейный дрейф между опорами остаётся `not-measured`: две точки не доказывают покадровую точность во всём интервале.

Событие содержит отдельно commandStart/End, actualInputs и пересчитанный sourceTimeMs. Эффект клика должен опираться на фактический `pointerdown`, а не на начало Playwright-команды. Скриншот связывается с eventId, состоянием URL и собственной измеренной геометрией. Пароли и URL query/fragment отсутствуют в журнале.

## Безопасная авторизация

`auth` открывает видимое окно с отдельным persistent profile в `%LOCALAPPDATA%/product-demo-toolkit/auth/<hash>`. Windows ACL ограничивает каталог текущим пользователем. Видео, screenshots, trace и HAR во время входа не включаются. Checkpoint содержит только технический статус. Ожидаемый locator задаётся в `auth.expectedLocator` или `readyLocator`.

Поддерживаются `auth(...,{mode:'login'|'status'|'reset'})`. Reset удаляет только вычисленный профиль этого demo-проекта. Профили не входят в output, preview или пакет. Перед записью защищённого приложения состояние проверяется без записи, затем тот же отдельный persistent profile открывается для capture.

Реальная локальная проверка: `/protected` → `/login` → видимое окно → кнопка «Войти в демо» → persistent cookie → закрытие/повторное открытие → проверка dashboard → запись. Кнопку нажал автоматизированный локальный тест, потому что пример не содержит паролей. Это подтверждает механику headed handoff/resume, но **не является реальным входом пользователя в сторонний сервис**. Сторонние OAuth/2FA/CAPTCHA, sessionStorage и особые SSO не протестированы. Локальная cookie имеет ограниченный Max-Age, поэтому переживает перезапуск.

## Кеш и границы доступа

Ключ capture зависит от действий, URL, геометрии, auth-стратегии, списка origins, версии backend и хешей локального web-кода. Voice/displayText/spokenText не входят в ключ. `demo.config.ts` исключён из общего сканирования: его влияющие на capture значения уже учтены отдельно. `.env`, секретные имена, auth, sources, node_modules, output и dist не читаются. Для встроенных примеров хешируются только явный сервер и соответствующая HTML-страница. Если сканирование ограничено размером, количеством или symlink, кеш не используется. У удалённого сервиса без локальных исходников изменения развёрнутой версии автоматически не определяются: нужен новый run для новой записи.

Кешированные PNG/WebM проверяются по SHA-256. Пути проверяются по фиксированному подкаталогу и `realpath`, с запретом traversal/symlink наружу. Origins и HTTP(S)-протокол проверяются на границе библиотеки; URL со встроенными credentials отклоняется. Запросы за пределы allowlist блокируются.

`ensureServer` запускает argv без shell, ждёт HTTP-ready, записывает только собственный PID и не завершает чужой процесс на занятом порту. Примеры обслуживают только явно перечисленные страницы через loopback, без файлового browsing. Discovery читает manifests/README/AGENTS только указанного проекта и возвращает данные для решения Codex; оно не притворяется универсальным выбором бизнес-сценария.
