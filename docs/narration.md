# Русская нейросетевая озвучка

Проверено 22 сентября 2026 на Windows. Выбран женский `ru-RU-SvetlanaNeural`, скорость 0%, провайдер `edge-neural`. Он использует онлайн-синтез Microsoft Edge через неизменённый сторонний клиент `edge-tts` 7.2.8. Это практический вариант без API-ключа и оплаты в проведённых запусках, а не официальный Azure API. Доступность потребительского сервиса и права на все коммерческие способы публикации не гарантируются лицензией Python-клиента.

Живой каталог Edge подтвердил женский Svetlana и мужской `ru-RU-DmitryNeural`; оба проверены синтезом. `ru-RU-DariyaNeural` присутствует в каталоге Azure, но не в проверенном каталоге Edge и не предлагается инструментом. Сравнение рассмотренных вариантов и первичные источники — [neural-voice-research.md](neural-voice-research.md).

## Запуск и передача текста

```powershell
node dist/cli.js voices preview --tts-provider edge-neural --allow-external-tts --voice female --speech-rate 0 --output output/neural-voice-samples
node dist/cli.js narrate --run output/basic-e2e --tts-provider edge-neural --allow-external-tts --voice female --speech-rate 0
```

`--allow-external-tts` разрешает отправку подготовленного `spokenText` сервису Microsoft. Видео, screenshots и файлы проекта этим адаптером не отправляются. Для текущего публичного вымышленного демо передача уже разрешена запросом пользователя; это не общее разрешение передавать приватный текст из следующих проектов. Настройка сохраняется в конфигурации конкретного запуска для возобновления работы. Секреты нельзя помещать в `spokenText`.

`auto` выбирает нейросетевой вариант только с разрешением внешнего TTS. Без разрешения он сообщает причину остановки. При сетевой ошибке или отсутствии выбранного голоса тихой замены на SAPI нет. `windows-sapi` доступен только при явном выборе как старый офлайн-вариант. Импорт локальной записи не требует разрешения внешнего синтеза.

## Установка и доступность

Первая операция `edge-neural` создаёт пользовательское Python-окружение и устанавливает фиксированную версию клиента и зависимостей. Нужен доступный Python 3.10+ и интернет к PyPI и сервису синтеза; административные права и ключи не нужны. Проверена Windows/Python 3.14.7. Пакеты устанавливаются под `%LOCALAPPDATA%/product-demo-toolkit/python/edge-neural-7.2.8/`, отдельно от runtime и проекта. `PRODUCT_DEMO_DATA_DIR` позволяет выбрать общий каталог данных. Реестр, TLS и политики безопасности не изменяются.

Настройки окружения фиксируются в `tts/edge-neural-install.json`; каталог голосов кешируется на 24 часа. `doctor` показывает установленный клиент и сохранённый каталог, но не объявляет сетевую доступность проверенной без реального запроса. Удалённая версия модели Microsoft не предоставляется; в кеше она обозначена `remote-model-unversioned`.

При испытании наблюдался единичный `NoAudioReceived`. Для такого временного сбоя и таймаута предусмотрена одна повторная попытка. Ошибка доступа не обходится и не заменяется другим голосом. После окончательной ошибки уже созданные сегменты сохраняются, повторный запуск использует кеш.

## Подтверждённые пробы и границы проверки

| Проба | Голос и скорость | Длительность | Источник |
|---|---|---|---|
| `output/neural-voice-samples/natural/female-ru.mp3` | Svetlana, 0% | 14.664 s | mono 24000 Hz, MP3 |
| `output/neural-voice-samples/calm/female-ru.mp3` | Svetlana, −3% | 15.120 s | mono 24000 Hz, MP3 |

Это две настройки одного женского голоса. Оба файла полностью декодированы, имеют ненулевой звук и измеренные уровни; peak исходных проб — около −4 dBFS. Пробы можно прослушать в локальных `index.html`. Метаданные и waveform не доказывают естественность: субъективное прослушивание агентом и сравнительная оценка произношения — `not-tested`. Выбор 0% — рабочее значение для нового демо, не заявление «лучший из всех голосов».

Исходные MP3 сохраняются без перекодирования. Микс 48000 Hz нужен монтажу; он не добавляет детализацию исходнику 24000 Hz. Для синтеза подтверждены расходы на API **0 USD**. `cost.externalRequests` считает попытки генерации речи, включая повторные; запросы каталога и установки зависимостей в этот счётчик не входят.

Кеш учитывает провайдера, версию клиента, голос, нормализованный текст, настройки скорости и словарь произношения. При чтении проверяются SHA-256 и полный decode. Изменение одной реплики пересоздаёт только её сегмент. Длительность берётся из аудио. Тексты не записываются в служебные ошибки, но находятся в storyboard и метаданных проекта; доступ к этим файлам контролирует пользователь.

Синхронизация монтажа и субтитров остаётся `segment`. Реально полученные sentence/word marks сохраняются как `providerMarks`, однако не объявляются пословным alignment всей композиции. `spokenText` должен быть подготовлен агентом: числа словами, корректная «ё», объяснение сокращений. `pronunciations` задаёт явные замены, например `{"DemoConsole":"Демо Консоль","API":"эй пи ай"}`. Вход — обычный текст, не shell и не пользовательский SSML. Один сегмент ограничен 5000 символами; `--speech-rate` принимает −10…10 процентов, без автоматического ускорения длинных фраз.

## Явный офлайн-вариант

`--tts-provider windows-sapi` использует публичные API установленного `System.Speech`. Проверены Microsoft Irina Desktop (female, `TTS_MS_RU-RU_IRINA_11.0`) и Microsoft Pavel (male, `MSTTS_V110_ruRU_PavelM`), mono 22050 Hz. Это старые системные голоса; их качество не приравнивается к нейросетевому. Исходные пробы сохранены в `output/voice-samples/`. Пол выбирается по метаданным и не подменяется; явно выбранное предпочтение сохраняется в пользовательских настройках, если не задан `--no-save-voice-preference`.

Модели Windows не копируются и не входят в пакет. Нужен PowerShell, допускающий локальный helper по действующей политике. `Bypass` не используется; отсутствие разрешённой оболочки или голоса даёт `blocked`. Дополнительный голос устанавливает пользователь через Windows Settings → Time & language → Speech. SAPI не поддерживает macOS/Linux.

## Импорт пользовательской записи

`narrate --run <путь> --narration-file <локальный.wav>` также принимает MP3. Исходник сохраняется; проверяются реальный audio stream, длительность, амплитуда и полное декодирование. Одна сцена получает файл как сегмент. Для нескольких сцен он воспроизводится непрерывно с начала композиции: `fullTrack`, `alignment: none`, смысловая синхронизация — `not-tested`. Монтаж должен оставлять достаточно времени для записи.

Для точного импорта по сценам рядом с WAV/MP3 можно создать `<имя.wav>.segments.json`:

```json
[
  {"sceneId":"intro","startMs":0,"endMs":3200},
  {"sceneId":"result","startMs":3200,"endMs":7100}
]
```

Все сцены должны присутствовать ровно по одному разу; диапазоны находятся внутри реальной длительности. Это предоставленные пользователем границы, а не автоматически вычисленный alignment.

## Монтаж звука и права

Микшер сохраняет отдельные WAV речи, музыки и смеси в `audio/<profile>/`. Музыка опциональна и берётся из явно выбранного локального файла с правами пользователя. Fade-in/fade-out и sidechain ducking проверены реальным FFmpeg-тестом: музыка ослаблялась более чем на 8 dB при активности голосового слоя. Диагностические сигналы этого теста не выдаются за речевой E2E. Финальный AAC отдельно проверяется на LUFS/true peak.
