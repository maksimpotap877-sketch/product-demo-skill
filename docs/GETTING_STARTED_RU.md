# Первый запуск: от репозитория до готового видео

Это руководство для локального компьютера. Полный путь проверялся на Windows; примеры команд ниже написаны для PowerShell. В репозитории есть сам toolkit, переносимый Skill, два небольших учебных сайта и документация. Использование учебного сайта помогает проверить установку; для настоящего продукта агент должен исследовать именно его исходники и интерфейс.

Если toolkit уже установлен и нужен новый ролик, переходите к [рабочему процессу](WORKFLOW_RU.md). Подключение агентов описано в [clients.md](clients.md), детали размещения runtime — в [INSTALL_RU.md](INSTALL_RU.md).

## 1. Подготовьте компьютер

| Компонент | Для чего нужен | Проверка |
|---|---|---|
| Git | Скачать и обновлять исходники | `git --version` |
| Node.js 22+ и npm | Исполнить CLI, собрать проект и рендерить Remotion | `node --version`, `npm --version` |
| FFmpeg и ffprobe | Измерить, смешать и проверить медиа | `ffmpeg -version`, `ffprobe -version` |
| Chromium или Microsoft Edge | Открыть продукт и записать сценарий | Проверяет `setup` / `doctor` |
| Python 3.10+ | Нейросетевая озвучка через `edge-tts` | `python --version` |
| Интернет | Установка зависимостей и выбранный онлайн-TTS | Нужен при соответствующих операциях |

Node.js, FFmpeg и Python должны быть доступны в `PATH` того процесса, где работает агент. После установки компонентов откройте новый терминал и новую сессию агента. Простое наличие программы в меню Windows не гарантирует её доступность командам.

Если компонента нет, используйте [официальную загрузку Node.js](https://nodejs.org/en/download), [Python для Windows](https://www.python.org/downloads/windows/) и [страницу загрузки FFmpeg](https://ffmpeg.org/download.html). На странице FFmpeg выбирается готовая Windows-сборка из указанных проектом источников, затем её каталог с `ffmpeg.exe` и `ffprobe.exe` добавляется в пользовательский `PATH`. Для Node можно использовать официальный ZIP в пользовательском каталоге; для Python нужен полноценный установщик с `venv`, не урезанный embeddable-архив. Не устанавливайте другую версию, если подходящая уже работает.

Toolkit не требует администратора, Docker или отдельного LLM API-ключа. Сам клиент агента использует ваш собственный аккаунт/провайдер. Графический ускоритель не обязателен: используется и программный encoder. Проверка `h264_qsv` может завершиться неудачно на системе без подходящего оборудования; отдельно смотрите рабочий `libx264`.

Python-пакет озвучки устанавливается в пользовательское окружение при первом запросе нейросетевой речи. Системный Python не модифицируется. Для явного старого офлайн-провайдера `windows-sapi` вместо Python нужны установленные русские Windows voices и PowerShell, допускающий локальный helper. Его качество отличается от нейросетевого голоса.

## 2. Скачайте и соберите toolkit

```powershell
git clone https://github.com/maksimpotap877-sketch/product-demo-skill.git
Set-Location product-demo-skill
npm ci
npm run build
node dist/cli.js --help
node dist/cli.js setup
node dist/cli.js doctor --json
```

Для закрытого репозитория GitHub потребуется доступ к нему. Вход выполняйте штатно через GitHub/свой Git-клиент; ключи и токены не нужно вставлять в чат или URL команды.

`npm ci` использует зафиксированные версии. `build` создаёт исполняемые файлы в `dist/`. `setup` проверяет браузер и при необходимости скачивает Playwright Chromium; команда не устанавливает автоматически все системные программы из таблицы. `doctor` создаёт отчёт и действительно проверяет короткое кодирование/декодирование.

Первый `doctor` может показать TTS как `blocked`, пока его пользовательское Python-окружение ещё не создано. Это не разрешение заменить голос на другой: выполните осознанную пробу ниже, затем повторите проверку.

Если PowerShell запрещает запуск `npm.ps1`, используйте доступный `npm.cmd` для npm-команд. Не отключайте execution policy, TLS или защиту браузера ради установки. Отсутствующий компонент нужно установить либо выбрать реализованный альтернативный путь, например импорт WAV/MP3.

## 3. Установите Skill для своего агента

Выберите одну команду:

```powershell
node dist/cli.js skill install --client codex --scope user
```

```powershell
node dist/cli.js skill install --client claude --scope user
```

Для Codex и Claude Code на одной машине:

```powershell
node dist/cli.js skill install --client both --scope user
```

Установщик создаёт отдельный runtime; после этого исходная папка toolkit не нужна для каждого запуска. Папка `.agents/skills/product-demo` предназначена Codex, `.claude/skills/product-demo` — Claude Code. OpenCode умеет читать эти расположения; настройка модели GLM описана отдельно в [clients.md](clients.md).

Проверьте статус с тем же выбранным `--client`. При необходимости обновите список Skills или откройте новую сессию агента.

```powershell
node dist/cli.js skill status --client codex --scope user --json
```

## 4. Проверьте выбранный голос

Для публичного текста встроенной пробы:

```powershell
node dist/cli.js voices preview --tts-provider edge-neural --allow-external-tts --voice female --speech-rate 0 --output output/voice-check
```

Создаются настоящий MP3, страница `output/voice-check/index.html` и `voices-manifest.json`. Откройте страницу и прослушайте запись. Выбран русский женский `ru-RU-SvetlanaNeural`; `--voice male` выбирает проверенный `ru-RU-DmitryNeural`. Варианты скорости меняют настройку одного диктора, а не создают нового.

`--allow-external-tts` разрешает отправку текста этой операции сервису Microsoft Edge. В проверенных запусках ключ и оплата API не потребовались. Это сторонний клиент потребительского сервиса; долговременная доступность и все коммерческие права на результат не гарантируются. Для приватного сценария допустимость передачи текста нужно определить отдельно. Подробности — [narration.md](narration.md).

При запрете внешнего синтеза используйте свою WAV/MP3-запись либо явно выберите `--tts-provider windows-sapi`. Автоматического переключения с нейросетевого голоса на SAPI нет. Сам факт полного декодирования файла не заменяет прослушивания.

## 5. Создайте отдельный учебный проект

Ниже — путь для Codex-установки. Если установлен только Claude Code Skill, возьмите launcher из его каталога, как показано в [clients.md](clients.md).

```powershell
$demoLauncher = Join-Path $env:USERPROFILE '.agents/skills/product-demo/scripts/run.mjs'
$demoProject = Join-Path $env:USERPROFILE 'Projects/DemoTrial'
$demoRun = Join-Path $demoProject 'demo-output/first'
node $demoLauncher init --project $demoProject --example basic
node $demoLauncher discover --project $demoProject --json
```

`init` не перезаписывает существующий `demo.config.json`. Учебный сайт копируется в `demo-site/` выбранного проекта, а конфигурация ссылается на него. Он содержит вымышленные данные. Не используйте этот пример вместо реального приложения без явного указания.

Теперь нужно понять продукт до записи. CLI собирает проверяемые выдержки, но не выдумывает их смысл за агента:

```powershell
node $demoLauncher analyze --project $demoProject --config demo.config.json --source demo-site/server.mjs --source demo-site/basic-web/index.html --json
```

Команда создаёт `demo.understanding.json` со статусом `draft`. Попросите агента прочитать выбранные исходники и вывод `readings`, заполнить назначение продукта, аудиторию, результат и сценарий, проверить условия успешных действий, затем поставить `ready`. Простая замена `draft` на `ready` не является анализом. Поля и порядок проверки разобраны в [WORKFLOW_RU.md](WORKFLOW_RU.md).

В Codex можно дать такой запрос:

> $product-demo В проекте DemoTrial создан учебный сайт. Прочитай его код и demo.understanding.json, осмысленно заверши анализ и проверь его. Затем выполни демо на 30 секунд: русский женский нейросетевой голос, web-60. Передачу публичного текста этого учебного сценария сервису озвучки разрешаю. Покажи MP4 и отчёт, отдельно укажи ограничения записи.

В Claude Code используйте `/product-demo` вместо `$product-demo`. Агенту нужны права читать выбранный проект и запускать установленные компоненты. Вход в аккаунт для встроенного сайта не требуется.

## 6. Запустите pipeline после готового анализа

```powershell
node $demoLauncher analyze --validate --project $demoProject --config demo.config.json --analysis demo.understanding.json --json
node $demoLauncher all --project $demoProject --config demo.config.json --analysis demo.understanding.json --run $demoRun --profile web-60 --voice female --tts-provider edge-neural --allow-external-tts --speech-rate 0
node $demoLauncher preview --run $demoRun --profile web-60
```

Preview показывает локальный адрес вида `http://127.0.0.1:<port>` и работает до остановки процесса. Откройте этот адрес в своём браузере. Видео не публикуется в интернете. Команда `all` последовательно выполняет запись, озвучку, план, рендер и техническую проверку. После неудачи сохранён checkpoint; продолжать нужно с диагностики, а не бесконечно повторять всю цепочку.

При проверке 144 fps выполните отдельно:

```powershell
node $demoLauncher benchmark --target-fps 144 --output (Join-Path $demoProject 'demo-output/benchmark') --strict-native-fps
```

У текущего Playwright backend исходные клипы измерены примерно в 25 fps. `master-144` означает композицию 2560×1440/144 fps, но не превращает этот источник в 144 уникальных состояния UI. При неподтверждённом native capture честный результат имеет статус `degraded`. Строгая проверка native fps останавливается с ненулевым кодом; это ожидаемая фиксация ограничения, а не повод снять ограничение молча.

## 7. Найдите результат и проверьте его

Главные файлы внутри `$demoRun`:

| Путь | Содержимое |
|---|---|
| `renders/` | Готовый MP4 и манифест рендера |
| `review/quality-report.json` | Результаты технических проверок |
| `review/quality-report.md` | Читаемая версия отчёта |
| `review/contact-sheet.png` | Обзор выбранных кадров |
| `review/provenance.json` | Связь источников, озвучки и результата |
| `narration/narration-manifest.json` | Голос, длительности, кеш, стоимость |
| `storyboard.json` | Текст и смысл отдельных сцен |
| `edit-plan-web-60.json` | Источники, камера, тайминг монтажа |

Просмотрите видео на обычной скорости и прослушайте речь. Проверьте, что действие действительно произошло, текст читается, камера показывает нужное, а конец фразы не обрезан. Контактный лист помогает оценить кадры, но не плавность. `ffprobe` и waveform помогают измерить файл, но не качество дикции.

Успешный технический экспорт и полностью принятый ролик — разные результаты. В отчёте используются `passed`, `failed`, `blocked`, `not-tested`, `degraded`. Не меняйте их только ради красивого итогового статуса.

## 8. Перейдите к своему продукту

Откройте репозиторий приложения в агенте и вызовите Skill. Укажите цель ролика, аудиторию, длительность и допустимость внешней озвучки. Агент должен читать реализацию нужного потока, а не только README: маршруты, компонент формы, обработчик сохранения, экран результата. Затем он создаёт конфигурацию под реальные locators и готовый анализ.

Для первого рабочего ролика обычно достаточно одного завершённого действия. Авторизацию в продукте пользователь выполняет в отдельном видимом окне без записи. Изменение текста, голоса или камеры не требует повторной записи, если нужные исходники уже сохранены. Полная инструкция по повторному монтажу и восстановлению — [WORKFLOW_RU.md](WORKFLOW_RU.md).
