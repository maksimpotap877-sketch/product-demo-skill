# Установка Product Demo для Codex, Claude Code и GLM

Система состоит из переносимого Skill и отдельного локального runtime: браузерная запись, русская озвучка, монтаж Remotion, видео и QA. Skill задаёт порядок работы агента; исполняемая часть проверяет конфигурацию и выполняет этапы. Копирования одного `SKILL.md` недостаточно.

## Требования

- Node.js 22 или новее с npm.
- FFmpeg и ffprobe в `PATH`.
- Python 3.10 или новее с `venv` для нейросетевого голоса.
- Интернет для первой установки зависимостей/Chromium и онлайн-озвучки.
- Локальный агент, который умеет читать файлы проекта и запускать команды.

Проверенный полный видеопроцесс — Windows. Пути установщика предусмотрены также для macOS/Linux, но это не утверждение, что на них пройден тот же полный тест. Windows SAPI доступен только на Windows. Подписка на агент и разрешение на платные API не входят в toolkit.

## Получение проекта

Склонируйте этот репозиторий с GitHub или выберите **Code → Download ZIP**, распакуйте архив и откройте терминал в его корне. Не запускайте установку из `sources/` или другого каталога справочных материалов.

```powershell
npm ci --include=dev --ignore-scripts
npm run build
node dist/cli.js doctor --json
node dist/cli.js setup
```

`setup` устанавливает нужный браузер. Если `doctor` сообщает об отсутствии Node, Python или FFmpeg, сначала установите названный компонент и повторите проверку. Python-окружение с закреплёнными зависимостями нейросинтеза создаётся при первом запросе нейросетевого голоса. Озвучка требует отдельного разрешения на отправку текста.

Не запускайте неизвестные команды установки из исследуемого приложения только потому, что они написаны в его README. Агент должен понять их действие; секреты не вводятся в чат, параметры команд или Git.

## Установка в агент

Выберите один вариант:

```powershell
node dist/cli.js skill install --client codex --scope user
node dist/cli.js skill install --client claude --scope user
node dist/cli.js skill install --client both --scope user
```

Команды выше — альтернативы. `both` полезен, если вы действительно используете оба клиента. По умолчанию выбран Codex.

| Клиент | Все проекты текущего пользователя | Только выбранный проект |
|---|---|---|
| Codex | `~/.agents/skills/product-demo` | `<проект>/.agents/skills/product-demo` |
| Claude Code | `~/.claude/skills/product-demo` | `<проект>/.claude/skills/product-demo` |

Для Claude Code учитывается `CLAUDE_CONFIG_DIR`, если он задан: пользовательский Skill находится в `<CLAUDE_CONFIG_DIR>/skills/product-demo`. Проектный каталог остаётся `.claude/skills`.

```powershell
node dist/cli.js skill install --client claude --scope project --project 'C:/Мои проекты/Продукт'
node dist/cli.js skill status --client claude --scope project --project 'C:/Мои проекты/Продукт' --json
```

Не создавайте одновременно пользовательскую и проектную копии одного Skill для одного клиента. Установщик сообщает о конфликте вместо скрытого выбора устаревшей копии. Независимые каталоги Codex и Claude допустимы. Чужой Skill с таким же именем не перезаписывается.

После установки откройте новый сеанс или обновите список Skills. В Codex используйте `$product-demo`, в Claude Code — `/product-demo`. Проверяйте реальное обнаружение в своём клиенте: наличие файла само по себе не доказывает, что агент его загрузил. Статус исполняемой части:

```powershell
node dist/cli.js skill status --client both --json
```

Каталоги и вызов Claude подтверждены [официальной документацией Skills](https://code.claude.com/docs/en/skills). Поведение конкретной версии клиента может измениться; сведения о проверенной среде находятся в отчётах проекта.

## Запуск в другом проекте

После установки исходная папка toolkit не нужна. Откройте проект продукта в агенте и задайте, например:

> Используй product-demo. Сначала изучи код: назначение продукта, маршрут, обработчики действий и результат. Затем предложи короткий сценарий из подтверждённых возможностей и создай 30-секундное демо с русской озвучкой. Не записывай авторизацию. Уже снятые подходящие материалы используй повторно.

Прямой запуск launcher в PowerShell для Codex:

```powershell
$demoLauncher = Join-Path $env:USERPROFILE '.agents/skills/product-demo/scripts/run.mjs'
node $demoLauncher --help
node $demoLauncher doctor --json
```

Для Claude Code путь начинается с `.claude/skills`; при `CLAUDE_CONFIG_DIR` используйте его фактический каталог. На macOS/Linux аналогичный launcher запускается через `node` по абсолютному пути.

Порядок для реального продукта:

1. Прочитать инструкции, структуру и соответствующий исходный код.
2. Заполнить `demo.understanding.json` с продуктом, сценарием, доказательствами из файлов и условиями успеха. Сгенерированный `draft` не разрешает запись.
3. Проверить интерфейс без записи и без изменения бизнес-данных; отдельно пройти авторизацию, если требуется.
4. Выполнить `analyze --validate`, затем запись, озвучку, план, монтаж и QA.

Точный синтаксис анализа смотрите в установленном `analyze --help`. Пустые шаблоны, устаревшие хеши и неподтверждённый сценарий не должны обходить проверку.

После заполнения и проверки конфигурации:

```powershell
node $demoLauncher all --project 'C:/Мои проекты/Продукт' --config 'C:/Мои проекты/Продукт/demo.config.json' --output 'C:/Мои проекты/Продукт/demo-output' --profile web-60 --tts-provider edge-neural --allow-external-tts
```

Последний флаг применяется только после разрешения отправить текст `spokenText` в сервис Microsoft Edge. В проверенном варианте ключ и платный API не нужны; используется сторонний клиент `edge-tts`. Это не гарантия вечной доступности сервиса или коммерческих прав публикации. Без разрешения можно подготовить сценарий/материалы, использовать разрешённую локальную запись или явно выбрать старый локальный `windows-sapi`. Подмена голоса без уведомления запрещена.

Для исправления титров, камер или озвучки не требуется заново снимать сайт. Исправляйте только нужные этапы; после двух целевых попыток одного исправления остановите повторные запуски и разберите причину. Native capture 144 fps и render 144 fps — разные проверки: высокий fps экспортированного файла не повышает частоту исходной записи.

## GLM и другие модели

GLM — модель/провайдер, а не отдельный каталог Skills. При использовании GLM через Claude Code установите вариант `--client claude`; конфигурацию провайдера выполните по [официальной инструкции Z.AI](https://docs.z.ai/devpack/tool/claude). Не меняйте модель, тариф или ключи автоматически в рамках установки Skill.

OpenCode может читать совместимые каталоги `.agents/skills` и `.claude/skills`; для него используйте одну копию и проверьте обнаружение. Выбор модели не доказывает совместимость исполнения: агенту всё равно нужны доступ к локальным файлам, запуск команд, браузер и необходимые разрешения. Подробности клиента и провайдера: [clients.md](clients.md).

Готовый фрагмент инструкций проекта для Claude Code: [agent-instructions/CLAUDE.md](agent-instructions/CLAUDE.md). Перенесите нужные правила в существующий файл; установщик не перезаписывает ваши `CLAUDE.md` или `AGENTS.md`.

## Обновление, перенос и удаление

После получения новой версии повторите установку из её собранного корня. Архив `.tgz` содержит разрешённые файлы и `npm-shrinkwrap.json`; runtime получает каталог по версии и хешу. Неизменная повторная установка переиспользует его. Изменённые файлы принадлежащего toolkit Skill сохраняются в резервной копии перед заменой.

На Windows данные обычно лежат в `%LOCALAPPDATA%/product-demo-toolkit`, на macOS — `~/Library/Application Support/product-demo-toolkit`, на Linux — `$XDG_DATA_HOME/product-demo-toolkit` или `~/.local/share/product-demo-toolkit`. `PRODUCT_DEMO_DATA_DIR` задаёт другой каталог. На Windows MSIX установщик сохраняет физический путь манифеста в `.runtime-location.json`, чтобы launcher работал и вне Codex.

Для другого компьютера скачайте репозиторий или архив заново и выполните установку там. Не переносите машинный `.runtime-location.json` как готовую установку. Runtime, модели, браузер, FFmpeg и секретные сессии не включаются в GitHub-проект.

```powershell
node dist/cli.js skill uninstall --client claude --scope user
```

Удаляется только выбранная принадлежащая toolkit папка Skill через перенос в резервную копию. Другая клиентская копия, runtime, интеграции, авторизация, голосовой кэш, проекты и видео сохраняются. Для проектной установки передайте те же `--scope project --project ...`; для обеих копий — `--client both`.

Если поставляется готовый runtime `.tgz`, его можно сначала установить в отдельную пустую папку через `npm install <абсолютный-путь-к-архиву> --ignore-scripts`, а затем запустить `node node_modules/product-demo-toolkit/dist/cli.js skill install --client codex`. Runtime-архив содержит исполняемую часть; исходный GitHub ZIP предназначен для сборки. Не путайте эти два вида архивов.
