# Монтаж и обновление до 0.4

Этот процесс одинаков для Codex, Claude Code и GLM в клиенте с файловыми инструментами. Агент читает Skill; локальный Node/Remotion исполняет монтаж. Доступ к Remotion MCP нужен только для поиска документации, не для рендера.

## Что исправлено

Ранее технически валидный MP4 мог содержать мелкий или обрезанный интерфейс, постоянный zoom, скачок с видео на другой снимок и затянутые сцены. Теперь пропорции проверяются по реальным файлам, рабочая рамка устойчива, камера по умолчанию статична, а конец клипа удерживается на его собственном последнем кадре. Общая длительность не заполняется пустыми паузами автоматически.

При жалобе на неровность сначала определите её вид: геометрия, скачок на склейке, потеря обновлений источника, движение курсора, камера или воспроизведение. Ровные PTS конечного файла не доказывают плавность исходной записи. Не делайте новую полную запись ради настройки камеры.

## Повторный монтаж

1. Прочитайте код функции и актуализируйте `demo.understanding.json`. Сохраните предыдущий экспорт.
2. Посмотрите исходники и запишите замечания с таймкодами. Убедитесь, что нужный результат действительно виден.
3. Составьте монтажный лист: назначение каждого плана, точный источник, in/out, реплика, область внимания, пауза чтения.
4. Измените `storyboard.json`: явные `clipId`/`screenshotId`, диапазоны, длительности и статичная камера либо обоснованные ключи. Сохранённую речь используйте повторно.
5. Выполните `plan`; просмотрите получившийся план. До длинного полного рендера проверьте короткий представительный фрагмент с теми же монтажными функциями и целевыми размерами.
6. Выполните `render`, затем `inspect`. Откройте видео и кадры. Сохраните редакционную проверку отдельной командой `review`.

Все команды ниже вызываются через `node <каталог-skill>/scripts/run.mjs` либо `node dist/cli.js` из toolkit:

```text
plan --run <абсолютный-каталог> --profile web-60
proof --run <абсолютный-каталог> --profile web-60 --scene <sceneId>
render --run <абсолютный-каталог> --profile web-60
inspect --run <абсолютный-каталог> --profile web-60
preview --run <абсолютный-каталог> --profile web-60
review --run <абсолютный-каталог> --profile web-60 --init
review --run <абсолютный-каталог> --profile web-60 --file <заполненный-json>
inspect --run <абсолютный-каталог> --profile web-60
```

Если редактируете `edit-plan-web-60.json` непосредственно, не запускайте `plan` после этого: он пересоздаст файл. Изменение голоса/реплики требует `narrate`; изменение камеры или диапазонов — нет. Сохранённые исходники не перезаписывайте.

`proof` принимает от одной до четырёх выбранных сцен (`--scene` можно повторять) и создаёт отдельный ролик для каждой. Он проверяет содержимое сцены, но не воспроизводит склейку с соседней сценой. Склейки, непрерывность движения и звука между сценами проверяйте в окончательном MP4. Звук фрагмента берётся из существующего микса в соответствующем месте основного таймлайна; финальная нормализация громкости полного экспорта к фрагменту не применяется.

Успешная проверка браузера в `doctor` подтверждает запуск через Playwright, а не Remotion. При первом развёртывании установите Chromium командой ниже; при сбое рендера с работающим Edge проверьте эту установку и повторите `proof` после диагностики. Renderer предпочитает установленный Chromium headless shell.

## Старые планы

- Несуществующий ID источника больше не заменяется случайным снимком. Исправьте ID по capture manifest.
- Неявный второй видеоплан больше не подставляет весь первый клип. Укажите нужный `clipId` и диапазон.
- Ключи камеры должны быть упорядочены, помещаться в сцену и оставаться разными после округления в кадры.
- Избыточную скорость/слишком короткий переезд камеры preflight отклоняет. Пересмотрите движение или используйте намеренную склейку крупностей.
- Общий `durationSec` — минимум. Если авторские сцены короче, уменьшите минимум или сознательно пересмотрите длительности. Не заполняйте дефицит одинаковым удержанием всех кадров.
- `holdPath` больше не заменяет последний кадр видео. Для другого состояния создайте отдельный план.
- `eventIds: []` не рисует постановочный курсор. Если курсор уже записан в видео, это правильный выбор.
- `type` последовательно печатает символы. `fill` мгновенно заполняет поле; это разные действия.

## Что означает результат QA

`review-candidate` означает, что файл можно посмотреть, но часть редакционной проверки отсутствует. `changes-required` требует устранить найденные дефекты. `reviewed` означает, что проверявший заявил проверку содержания, кадрирования, полного движения и звука, а технические проверки не нашли ошибок.

Запись `review` привязана к SHA-256 конкретного MP4 и его длительности. После любого нового экспорта старое заключение не применяется. Для движения метод — реальный просмотр всего файла при обычной скорости; для голоса — прослушивание всего конечного звука. Если агент не располагает этими возможностями, он оставляет `not-tested` и передаёт видео человеку. Автоматическая запись JSON не превращает непроведённую проверку в проведённую.

Отдельно указываются native capture144 и render144. Неподтверждённый native144 остаётся ограничением даже у хорошо смонтированного ролика. Ни заголовок файла, ни плавная анимация титров не добавляют исходнику новые состояния.

## Обновить установленный Skill

```powershell
npm ci
npx playwright install chromium
npm run build
node dist/cli.js skill install --client both --scope user
node dist/cli.js skill status --client both --scope user --json
```

Проверяйте установленный launcher из другого проекта. Изменить только Markdown в исходном репозитории недостаточно: исполнитель также должен обновиться. Детали подключения клиентов и MCP — в [clients.md](clients.md), права и авторизация — в [Skill: вход и авторизация](../skills/product-demo/references/auth.md).
